# Current Project State

Use this file as the compact continuation anchor for humans and agents. Keep stable project purpose in `PROJECT.md`.

Allowed values:

- `phase`: `discover | explore | develop | validate | deliver | archive`
- `status`: `active | paused | blocked | complete`
- `rigor`: `E | R | V | P`

## Last validated state

State the most recent result, workflow state, or commit that has actually been checked, naming whether the evidence establishes implementation verification, scientific validation, or both. Do not describe planned work as validated.

## Key supported findings

- Add findings supported by the current evidence.

## Emerging findings

- Add observations or candidate findings that still need confirmation.

## Important negative or contradictory findings

- Record results that constrain interpretation, contradict expectations, or prevent repeated failed work.

## Current blocker

State the most important current blocker, or `None`.

## Open questions

- List unresolved scientific, computational, or operational questions.

## Pending decisions

- List decisions that require human, scientific, or project-lead judgment.

## Next experiment or analysis

State the next evidence-producing step.

## Next deliverable

State the next concrete output that should exist.

## Next recommended action

State one actionable next step.

## Next authorization boundary

State the next action that must not happen automatically, such as commit, push, merge, dependency change, external upload, public release, network/security change, or destructive operation.

## Deadline / timing constraints

Record material deadlines or timing dependencies.

## Continuation notes

Link the minimum additional context needed by the next browser/desktop ChatGPT conversation, Codex session, independent review, or human-only continuation.
